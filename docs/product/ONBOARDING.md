# Product: Onboarding

## Description

The onboarding flow introduces the user to Mercury and collects the minimum information needed to build a personalized news experience from the first session.

The onboarding should be short, modular, and skippable only where appropriate.

## Current shipping scope (2026-07-10, issue #133)

The onboarding is a **four-step paged flow** shown on first launch,
gated by `UserPreference.hasCompletedOnboarding` exactly as before
(tri-state in `AppRouter`; the flag flips only on the final Continue).

1. **Intro** — one paper-styled page that explains the app in three
   lines (Italian outlets, stories grouped by topic, AI summaries).
   Zero I/O: no store reads, no network.
2. **Fonti** — the existing outlet picker (single-region catalog,
   auto-enabled Italy, per-outlet toggles). **Must not fetch or load
   any article** — selection persists preferences only; the first
   feed refresh still fires after the final step.
3. **Interessi** — suggested chips (Italia, Politica, Ambiente,
   Economia, Sport, Tecnologia, Cronaca, Esteri, Salute, Cultura,
   Scienza) plus a free-text field for custom interests. Persists to
   `UserPreferenceEntity.preferredTopics`. A footnote explains that
   the personalized "Per te" feed requires the AI provider configured
   in the next step. Skippable (no interests → Per te shows its
   configure/empty state).
4. **Provider AI** — compact provider setup (provider picker + API
   key; same behavior as Settings → AI provider, shared view model).
   Skippable: everything except Per te and summaries works without it.

The same pickers are mounted in Settings so every choice can be
revisited (see `docs/features/SETTINGS.md`).

**No fetching before Continue** (issue #87): while onboarding is
incomplete, no RSS fetch may run. `AppRouter` treats the persisted flag
as tri-state — `nil` (still loading) renders a placeholder, never
`HomeScreen` — and `HomeViewModel.loadInitialFeedIfNeeded` is a no-op
until `hasCompletedOnboarding` is `true`. The first feed refresh
therefore always runs against the source set picked during onboarding.

---

## Goals

The onboarding must allow the user to configure:

* preferred countries / source regions
* preferred sources
* preferred language
* automatic translation behavior
* general topics of interest

It should also explain that Mercury uses AI features and that AI-generated content must always be clearly labeled.

---

## Onboarding Steps

## Step 1 — Welcome

### Purpose

Introduce Mercury and explain the value proposition.

### Content

* Mercury aggregates news from multiple sources
* Mercury can summarize, categorize, and translate content using AI
* AI-generated content will always be labeled

### Actions

* Continue
* Optional: skip onboarding

---

## Step 2 — Source Geography Selection

### Purpose

Let the user define which source pools are relevant.

### Options

* Global
* Europe
* Country-specific selections

### Example

* Italy
* France
* Germany
* Spain
* Global sources

### Rules

* **Italy-only scope (issue #102)**: the shipping catalog exposes a single
  region (Italy). The region layer stays in the model and the multi-region
  catalog entries stay in the source behind the `MERCURY_MULTI_REGION`
  compile flag, but the UI never shows region selection: onboarding lists
  the Italian outlets directly and the single region is auto-enabled.
  Re-enabling other regions is future work, out of thesis scope.
* user can enable/disable individual outlets
* **Opt-in per outlet** (issue #78): all outlets of the auto-enabled region
  start ON; the user can hide individual outlets. See
  `docs/features/SETTINGS.md` § Feed sources.

---

## Step 3 — Source Selection

### Purpose

Let the user choose preferred publishers.

### Inputs

* filtered source list based on previous geography selection

### Behavior

* sources should be grouped by country
* sources should be searchable
* sources should be selectable/deselectable

### Rules

* users may keep default recommended sources
* users may refine later in settings
* hidden / excluded sources should also be supported later

---

## Step 4 — Preferred Language

### Purpose

Define the main reading language.

### Example options

* Italian
* English
* Spanish
* French
* German

### Rules

* preferred language affects feed presentation
* original article language should still be stored
* app should preserve source language metadata

---

## Step 5 — Translation Preferences

### Purpose

Define whether foreign-language content should be translated.

### Options

* Never translate automatically
* Translate only when article language differs from preferred language
* Always prefer translated version when available

### Rules

* translated text must always be labeled as AI-generated
* original text should remain accessible
* user must be able to switch between original and translated version

### Labeling Requirement

Any translated title, summary, or body text generated by AI must visibly state that it was generated or transformed by AI.

---

## Step 6 — Topic Interests

### Purpose

Collect initial high-level interests.

### Suggested category examples

* Technology
* Business
* Politics
* Economy
* Science
* World
* Sports
* Culture
* Health

### Suggested topic examples

* AI
* Apple
* Cybersecurity
* Startups
* Gaming
* Climate
* European Union

### Rules

* users may select categories and/or topics
* the system should work even if the user selects nothing
* initial preferences should bias feed ranking, not hard-filter all content

---

## Step 7 — Confirmation

### Purpose

Summarize the selected setup before entering the app.

### Summary should include

* selected countries / source regions
* selected sources
* preferred language
* translation mode
* selected interests

### Action

* Start using Mercury

---

## Interest Evolution After Onboarding

## Description

Initial onboarding captures broad preferences only.

Over time, Mercury should refine the profile based on usage.

### Example progression

* Technology
* Technology > Gaming
* Technology > Gaming > Crash Bandicoot

### Signals used

* opened articles
* reading duration
* repeated topic interactions
* bookmarked content
* ignored topics or sources

### Rules

* evolution should be gradual
* inferred interests should not silently replace explicit user preferences
* inferred interests should be editable by the user

---

## UX Principles

* onboarding should feel lightweight
* avoid too many required decisions
* allow later editing in settings
* explain AI clearly but briefly
* always surface AI-generated content transparently

---

## Output

At the end of onboarding, Mercury should create an initial local user profile with:

* selected source regions
* selected sources
* preferred language
* translation mode
* initial category interests
* initial topic interests

---

## Notes

* onboarding should optimize first-session relevance
* onboarding should not overfit the feed too aggressively
* explicit user choices should have higher priority than inferred interests
